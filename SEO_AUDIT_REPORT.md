Всё через Metadata API (`generateMetadata` / `export const metadata`), ручных манипуляций `<head>` нет.

| Страница | Файл | Шаблон title |

### Проблемы

1. **Дубль бренда в title**: шаблон `${product.brand} ${product.name}` при том, что имя уже содержит бренд → «Ceresit Грунтовка Ceresit CT 17», «Polifarb Емаль Polifarb DekoMal». Мусорный заголовок в выдаче.
2. **Нет коммерческого интента в title товара**: отсутствует «купити», «ціна» — то, что спека требует в Фазе 2. Слово «купити» есть только у категорий/брендов.
3. **Длина title 73–104 симв.** — видимая часть в Google ~60–65; хвост с ценой и «| FIXLINE» обрезается.
4. **Дубль фасовки**: «...0,28 кг 280 г» (volume добавляется, если его нет в name, но проверка `name.includes(volume)` не ловит другую запись той же фасовки — `app/product/[id]/page.tsx:38-39`).
5. **Цена в title берётся из `stock.price_unit`** (строка 37), а на странице розничная `price_retail`/`price_promo` (строки 124-127) → расхождение title и страницы (подтверждено: title 315 грн, JSON-LD 339 грн — см. п. 4).
6. **Twitter card статичная** — задана один раз в `app/layout.tsx:38-42` и нигде не переопределяется: у всех товаров одинаковые twitter:title/description.
7. Позиционирование по умолчанию «оптом / B2B» в layout-default и fallback-описаниях — конфликтует с розничным поисковым интентом.
8. Двойные пробелы в name («глибокопроникаюча,  5 л») попадают в title/H1/JSON-LD.

Плюс: Харькова в шаблонах и так нет — обновлённая спека (национальный таргетинг) уже соблюдается.

## 2. Рендеринг

**Стратегия товарной страницы: SSR на каждый запрос** — `export const dynamic = 'force-dynamic'` (`app/product/[id]/page.tsx:30`), т.к. страница читает Supabase-сессию (опт/розница, строки 98-103). Данные кэшированы через `unstable_cache` revalidate 60с (`lib/supabase.ts:265-268`). Остальное: главная ISR 300с, категории ISR 3600с.

В initial HTML (проверено curl):
- ✅ H1-название (`page.tsx:217`), бренд, артикул, наличие, цена (240-254);
- ✅ описание — активная вкладка «Опис» рендерится при SSR (`ProductTabs.tsx:36,74-84`);
- ✅ оба JSON-LD (BreadcrumbList, Product);
- ❌ **характеристики — НЕТ в HTML**: `ProductTabs.tsx:86-101` — таблица рендерится только при `tab === 'chars'` после клика; в HTML продакшена `chars-table` отсутствует (grep = 0). Для Google характеристики товара невидимы; в JSON-LD их тоже нет (нет `additionalProperty`).
- ❌ **тексты отзывов — клиентский fetch** `/api/reviews` (`ProductReviews.tsx:33`); в HTML только агрегат рейтинга.

### sitemap — `app/sitemap.ts` (динамический, revalidate 3600)
- Товары: все **активные** (`is_active = true`, `lib/supabase.ts:73`) → `/product/{sku}` (строки 60-65). Факт: **768 uk-товаров** в sitemap при ~1435 в каталоге — либо ~половина товаров неактивна, либо покрытие неполное. **Проверить в БД.**

**Мёртвый код**: `lib/meta.ts:1-10` — неиспользуемый хелпер `hreflang()`, возвращающий одинаковый URL для uk/ru (мина при случайном использовании — удалить).

### Баги в фактическом JSON-LD (страница 1203-002)

1. **name с двойной фасовкой и дублем бренда**: `"Ceresit Грунтовка Ceresit CT 17 глибокопроникаюча,  5 л 5 л"` — volume дописывается без проверки вхождения.

3. **image — относительный путь** `"/img/products/ceresit/1203-002-....webp"` — для Rich Results нужен абсолютный URL.
4. Нет характеристик (`additionalProperty`) — согласуется с п. 2.

## 6. Внутренняя перелинковка

Работает:
- Хлебные крошки — настоящие `<Link>` + BreadcrumbList: товар `app/product/[id]/page.tsx:199-207`, категория `app/shop/[category]/page.tsx:116-128`. Цепочка: Головна → родительская категория → категория → товар.
- Карточки листинга — `<Link href="/product/{sku}?from=shop">` (`app/shop/ShopClient.tsx:117`).
- «Схожі товари» — до 5 товаров категории, реальные ссылки (`RelatedCarousel.tsx:111,115`), но выборка статичная (`lib/supabase.ts:271-282` — у всех товаров категории почти одинаковая).
- Футер на каждой странице: все родительские категории + бренды (`app/components/Footer.tsx:131-166`).
- Мета-полоса товара → категория и бренд (`page.tsx:289-294`); ссылка на тематическую статью блога (303-310).
- Глубина клика: товар из превью главной — 1 клик; типовой товар — 2 клика.

Проблемы:
1. **Пагинация листинга — кнопка, не ссылки**: в HTML категории только первые 24 товара (`ShopClient.tsx:299,1126,1156-1166`). Товары глубже 24-й позиции доступны краулеру только через sitemap и related-карусель → слабый ссылочный вес большинства товаров.
2. **Сайдбар категорий в /shop — `<button>` + pushState** (`ShopClient.tsx:747-760,798`), не `<a href>` — дерево подкатегорий из листинга не краулится (компенсируется футером и sitemap).
3. `?from=shop` в ссылках карточек — параметризованные URL; canonical это гасит, но чистые URL были бы лучше.
